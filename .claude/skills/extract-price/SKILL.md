# extract-price

## Контракт

- **Вход:** один URL страницы товара (например,
  `https://www.jib.co.th/web/product/readProduct/76790/51/VGA--...`).
- **Выход:** строго один JSON-объект. Два варианта, различаемые полем
  `status` — это и есть контракт, читай его внимательно, он важен для
  того, кто вызывает `extract-price` (например, `tracker`):

  **Успех** (`status: "ok"`) — цену удалось прочитать:

  ```json
  { "status": "ok", "regular_price": 13500, "sale_price": null, "has_credit": true }
  ```

  - `regular_price` — `number | null`. Обычная (полная) цена товара без
    скидки. При `status: "ok"` это всегда число, никогда `null` — `null`
    возможен только при `status: "error"` (см. ниже), где означает
    «данные неизвестны», а не «цены нет».
  - `sale_price` — `number | null`. Цена по скидке/акции, если она есть на
    странице; `null`, если скидки нет. Это **единственное** место в
    контракте, где `null` — легитимное, а не аварийное значение: оно
    означает «скидки нет», а не «данные неизвестны».
  - `has_credit` — `boolean`. `true`, если страница явно предлагает
    рассрочку/кредит на товар, иначе `false`.

  **Ошибка** (`status: "error"`) — цену прочитать не удалось (см. Шаг 6):

  ```json
  { "status": "error", "regular_price": null, "sale_price": null, "has_credit": null, "error": "HTTP 404" }
  ```

  - `regular_price`, `sale_price`, `has_credit` — все `null`. Это не
    «цены нет» и не «рассрочки нет» — это «неизвестно, страница не
    отдала данные». Не путай этот `null` с легитимным `sale_price: null`
    из успешного случая: там `null` — содержательный ответ, здесь —
    отсутствие ответа.
  - `error` — короткая строка с причиной (HTTP-код, «капча», «нужен
    вход», «на странице нет цены» и т.п.) — для диагностики у вызывающей
    стороны.

  Числа — обычные числа (не строки), без символа валюты и разделителей
  тысяч. Валюта в контракт не входит — если она нужна отдельно, сообщи её
  текстом рядом с объектом, но не добавляй как поле в сам объект.

  В финальном ответе не должно быть ничего, кроме этого JSON-объекта (без
  обёртки в лишний текст, без "вот цена:" и т.п.), если пользователь явно не
  попросил дать пояснения. **Вызывающая сторона обязана сначала проверить
  `status`** и только при `"ok"` читать цены как реальные данные — при
  `"error"` три поля с ценами — просто заполнители, а не признак того,
  что скидка/рассрочка/цена и правда пропали.

## Шаг 1. Получить содержимое страницы

1. Загрузи HTML страницы по переданному URL (инструментом веб-доступа или
   `curl` с обычным браузерным `User-Agent`).
2. Если получен HTTP-код ошибки, редирект на другую страницу (например,
   "товар не найден") или капча — не выдумывай цену. Сообщи об этом и верни
   объект-заглушку из Шага 6.
3. Если сайт рендерит цену через JavaScript и в исходном HTML её нет (тело
   страницы почти пустое) — попробуй достать данные из встроенного JSON
   (см. Шаг 2, пункт 1) или, если инструменты позволяют, отрендерить
   страницу в браузере перед разбором.

## Шаг 2. Найти цену на странице (по приоритету источников)

1. **Структурированные данные (самый надёжный источник).** Поищи
   `<script type="application/ld+json">` с `"@type": "Product"` и полем
   `offers.price` / `offers.priceCurrency`. Это число — цена, которую
   реально платит покупатель сейчас (т.е. цена с учётом скидки, если она
   есть).
2. **Meta-теги**, если JSON-LD нет: `<meta property="product:price:amount">`,
   `<meta property="og:price:amount">`, `itemprop="price"`.
3. **Видимая разметка**, если ничего из выше не нашлось: ищи число рядом со
   словами "ราคา" / "price" / "цена" / "стоимость". Пример устойчивого
   паттерна (сайты на движке вроде jib.co.th):

   ```html
   <div class="price_block">
     <div class="price">ราคา</div>
     <div class="unit">บาท</div>
     <strong>13,500</strong>
   </div>
   ```

   Текст внутри `<strong>` рядом с меткой цены и валютой — это текущая цена.

Если ни один из трёх источников не дал числа — переходи к Шагу 6.

## Шаг 3. Разделить на обычную цену и цену со скидкой

Число, найденное в Шаге 2, — это **текущая цена** (та, что фактически
платится). Дальше нужно понять, есть ли скидка:

- Поищи рядом индикатор скидки: перечёркнутое число (класс вроде
  `strikethrough-diagonal`, тег `<del>`/`<s>`, `style="text-decoration:
  line-through"`), подпись "ลดทันที", "-NN%", "скидка", "было", "sale",
  "discount", "old price" и т.п.
- **Если индикатор есть:** `sale_price` = текущая цена из Шага 2,
  `regular_price` = число из перечёркнутого/старого значения.
- **Если индикатора нет:** `regular_price` = текущая цена из Шага 2,
  `sale_price` = `null`.

Пример (jib.co.th, товар со скидкой):

```html
<div class="price_block">...<strong>2,090</strong></div>
<div class="price_discount">
  <span class="price">ลดทันที&nbsp;900.-</span>
  <span class="discount">
    <span class="strikethrough-diagonal">2,990</span>.- <span>-30%</span>
  </span>
</div>
```

→ `regular_price = 2990`, `sale_price = 2090`.

Пример (jib.co.th, товар без скидки — блок `price_discount` пуст):

→ `regular_price = 13500`, `sale_price = null`.

## Шаг 4. Определить `has_credit`

`true`, если на странице явно упоминается рассрочка/кредит на товар:
кнопка/блок вида `class="installment_branch"`, текст "ผ่อนชำระ",
"installment", "0% credit", "в рассрочку", "в кредит" и т.п. рядом с
покупкой товара. Иначе — `false`.

## Шаг 5. Нормализовать число

1. Убери всё, что не цифра и не разделитель дробной части: пробелы (обычные
   и неразрывные ` `), символы и слова валюты (`฿`, `บาท`, `$`, `₽`,
   `руб.`, суффикс `.-` и т.п.), разделители тысяч (запятые/пробелы внутри
   числа, например `13,500` → `13500`).
2. Приведи десятичный разделитель к точке и преобразуй строку в число
   (`number`), а не оставляй строкой.

## Шаг 6. Если цена не найдена

Если страница не открылась (Шаг 1, пункт 2: HTTP-ошибка, редирект на
«товар не найден», капча, таймаут) **или** страница открылась, но после
Шагов 1–3 на ней нет ни одного числового значения цены (товар «под
заказ» без цены, нужен вход в аккаунт и т.п.) — это одна и та же
ситуация: данные о цене недоступны. Не выдумывай цену и не подставляй
`false`/`null` как будто это содержательный ответ — верни явный статус
ошибки:

```json
{ "status": "error", "regular_price": null, "sale_price": null, "has_credit": null, "error": "краткая причина" }
```

`error` — короткая причина одним словом/фразой: `"HTTP 404"`, `"редирект
на страницу «товар не найден»"`, `"капча"`, `"на странице нет цены"` и
т.п. Дополнительно вне JSON можно коротко пояснить причину читателю —
это единственный случай, когда допустим текст помимо самого объекта.
